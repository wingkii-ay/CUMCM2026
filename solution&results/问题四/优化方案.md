## 一、诊断：0 时的钱花在哪

### 1.1 症状

修正前 Q4-3 比 Q4-2 贵 **124,253.61 元**。但 Q4-3 的可行集**包含** Q4-2（取 A=G 即退化为 Q4-2），所以 Q4-3 的真正最优值不可能高于 Q4-2。费用反超只可能来自近似策略的次优性——而问题三里同一对比是 Q3 比 Q2 **便宜约九万**，方向相反，说明这不是"额外信息有害"，而是优化实现漏了一项。

### 1.2 分项对照（主口径，Q4-3 减 Q4-2）

| 项目 | 修正前 | 修正后 |
|---|---:|---:|
| 原计划费 | +181,603 | **−1,179,148** |
| 增购费 | +224,038 | +1,263,615 |
| 应急费 | −281,387 | −165,345 |
| **合计** | **+124,254** | **−80,879** |

修正前 Q4-3 的"原计划费"高于 Q4-2，即**日前承诺量本身偏高**——这与"多用了信息反而更贵"直接矛盾，是指向缺陷的关键线索。

### 1.3 根因（`core.py` 的 `plan()`，修正前为第 80 行；现为第 90 行）

```python
obj[g]=(1.5 if original is not None else 1.)*p
obj[q]=5*price/s                      # ← 0时对所有时段一律按5倍应急给缺额定阶
```

`plan()` 被两处调用：

- **0 时**（`original is None`）：G 是全天共享承诺，场景缺额按 5p 定价。
- **节点**（`original` 非空，t=36/72/108）：`obj[g]=1.5p`，即增购按 1.5p，与合同一致。

于是 0 时的计划与节点实际面临的价格**不一致**：0 时认为"节点之后短缺 1kWh 要花 5p"，节点实际只需 1.5p。这是教科书式的 newsvendor 分位错位：

| 缺额定价 | 承诺应覆盖的分位 | 结果 |
|---|---|---|
| 5p | P(需要) > 1/5 = 20% → **80% 分位** | 系统性多承诺 |
| 1.5p（合同价） | P(需要) > 1/1.5 ≈ 67% → **67% 分位** | 正确 |

多承诺的部分**无法回退**：`core.py` 在调整层把 A 的下界钉在 G 上（`bounds[g[t]]=(original[t]/1000,None)`），`decrease_kwh` 恒为 0，`validate()` 有断言。多买的电只能落进"未利用"。

### 1.4 佐证

- 问题三的 `battery_core.py:141` 对可调整时段正是按 1.5p 定价（`obj[g]=p−1.5*p*adj`、`obj[a]=1.5*p*adj`，配 `a≥g`）。该写法与"直接把节点后缺额定在 1.5p"**同解**（`p·G+1.5p·(A−G)` 的线性化），问题四未把这一处理带过来。其 docstring 原文即警告："问题二口径把缺口一律按 5p 应急定价，等价于把 0 时计划抬到高分位，在问题三里系统性地多承诺。"
- 修正前 Q4-3 的 0 时承诺量 G 比 Q4-2 **高约 22.4 万 kWh**（未利用量同时高 37.1 万 kWh）；修正后 G 反过来比 Q4-2 **低 160.8 万 kWh**，未利用量低 61.6 万 kWh。方向与幅度都指向"0 时计划抬得太高"。
- 附件 3 的 0 时光伏预报相对实际偏低约 1.17%（Q4-2 用的历史均值偏低约 0.31%），使 Q4-3 的 0 时输入本身偏悲观；叠加上一条，正好解释了这部分过量承诺。

## 二、优化方案

### 方案① 节点后缺额按合同增购价定阶 【✅ 已实施并核验】

**改法**（`core.py`）：

```python
SHORT_ADJ=1.5
def plan(..., adj_from=None, adj_coef=SHORT_ADJ):
    coef=np.full(n,5.) if adj_from is None else np.where(np.arange(n)>=adj_from,adj_coef,5.)
    obj[q]=coef[None,:]*price/s
```

`simulate_day` 在 `branch==3 and policy!='only0'` 时传 `adj_from=36`，其余情形保持 `None`：

| 配置 | `adj_from` | 理由 |
|---|---|---|
| Q4-2 全天 | None | A≡G，缺口只能应急，5p 是对的 |
| Q4-3 `policy='only0'` | None | 该对照不做节点调整，无增购机会 |
| Q4-3 其余策略 | 36 | 首个调整节点在 6 时，t≥36 才可增购 |

**边界说明**：t<36 的时段在当天第一个调整节点之前，缺口确实只能按 5p 应急，**保持 5p 是对的**。被修正的只有节点之后的时段。

**实测代价**（公平边界协议，6000 起终库存，`study_shortcoef.py`）：

| 指标 | 修正前 | 修正后 | 变化 |
|---|---:|---:|---:|
| Q4-3 全年费用 | 14,535,182.50 | **14,330,482.52** | **−204,699.98（−1.41%）** |
| 0 时承诺 G | 21,977,340 kWh | 20,146,000 kWh | −1,831,340（−8.3%） |
| 未利用电量 | 3,047,003 kWh | 2,060,610 kWh | −986,393（−32.4%） |
| 应急电量 | 27,136.95 kWh | 53,751.22 kWh | **+26,614（+98%）** |

即：少承诺 183 万 kWh → 少浪费 99 万 kWh，代价是应急增加 2.7 万 kWh，净省 20.5 万元。**应急电量上升而总费用下降**，说明修正前"压低应急"是靠过量承诺换来的，账面上好看而已。

**副作用（必须披露）**：修正使 `stale_all`（全天沿用 0 时光伏预报）的对照值由 14,536,420 升到 14,872,397（+335,977）。原因是该策略下节点拿不到比 0 时更新的光伏预报，"节点能按 1.5p 补上缺额"这一假定不成立，缺口落到 5 倍应急。因此 §四 的 `all` vs `stale_all` 差值（由修前的 1,237 元变为 541,914 元）应读作**更新的预报与它使日内调整真正可用的联合价值**，不是预报纯价值。该项已写入答案与验收记录。

**风险**：低。只改 0 时 LP 的一个目标系数，实时层、调整层、账本口径、Excel 模板全部不动；`verify.py`、`solve.py --smoke` 的因果性与物理断言修正后仍全过（分支 2 决策逐位不变，最大漂移 1.8×10⁻¹²）。

### 方案② 允许调整向下（A<G 按 0.5p 退款） 【⏹ 不再执行】

**设想**：合同写的是"净差计费一次"，A<G 时按 0.5p 退款，那多承诺就是可部分回收的，`decrease_kwh` 不该恒为 0。

**不执行的理由**：

1. 问题三的模型合同 K2 明确声明"计划全额收费，不退款"（`题目分析报告.md` §2），问题四沿用同一口径。单独改问题四会让两问的结算解释不一致。
2. 题面本身对退款/锁价有歧义，两问统一按"不退款"是一种**声明口径**，不是缺陷。
3. 收益不明：退款价 0.5p 低于增购价 1.5p，可回收比例有限，且会引入逐笔计费与"撤回前一节点增购"的时序歧义。

**实测代价**：未做对照实验，无实测数据；上表收益为估计，不得作为结论引用。

**若要做**：改 `core.plan` 的 `bounds[g[t]]` 下界并在账本中计入 `decrease_cost_yuan`（该列已在 `simulate_day` 与 Excel 口径中预留），同时重跑两问以保持一致。

### 方案③ 按回测费用挑缺额系数 【❌ 已否决】

`study_shortcoef.py` 的扫描显示，`all` 策略下全年费用在系数 2.0 处最低（14,315,163），比合同价 1.5 还低 15,320 元（0.11%）。

**否决**：按全年实际费用回头挑系数属于**事后择优**，答案 §一 已明确不作此声明。系数是合同量（节点增购的边际价），不是可调经验参数；1.5 与 2.0 的差距远小于单年回测噪声（见下方区间），没有理由偏离合同价。

**但扫描本身有诊断价值**：它显示 `all` 与 `stale_all` 对系数的偏好**方向相反**（前者偏好 1.5–2.0，后者单调偏好 5.0），说明该系数不是随手可取的常数，而必须与"节点实际能执行多少增购"一致。这正是方案① 副作用（`stale_all` 变差）的机制来源。扫描结果存于 `results/short_coef_sensitivity.csv`。

## 四、约束与红线

修正过程必须维持以下性质，否则结果不可信（本次修正后全部复核通过）：

1. **因果性**：0 时不得读取当天未来实际值；`verify.py` 的 `forecast_release_hour<=((slot-1)//36)*6` 断言必须继续成立。另由 `audit_leakage.py`（扰动电池 + 整年库存结转）与 `audit_lag.py`（严格因果回退对照）独立送检。
2. **物理可行性**：物料平衡、储能动态、SOC∈[1200,10800]、功率≤5000kW、禁止同时充放——由 `verify.py` 独立复核。
3. **只读原附件**：不得修改附件 2/3/4/5。`workbook()` 只读取 `附件5` 的模板并另存到本项目目录。
4. **可复现**：确定性，无随机源；`run_all.py` 为唯一入口。
5. **不改账本口径**：`J_42=Σp(G+5e)`、`J_43=Σp[G+1.5u+0.5v+5e]` 与实际结算价 p 不变；本次只改**计划**用的缺额系数，不改实际计费。
