### 1.3 决定性发现：应急购电 89% 来自周末

| | 天数 | 预测 MAE | 应急购电量 | 未使用量 |
|---|---:|---:|---:|---:|
| 工作日 | 238 | 64.6 kWh | 36,772 | 4.00M |
| **周末** | **96** | **94.7 kWh** | **304,133** | 2.06M |

周末仅占 29% 的天数，却贡献 **89.2%** 的应急购电。折合单日：周末 3,168 kWh vs 工作日 154 kWh，**相差约 20 倍**。

**根因**（`solve_q2.py:56-57`）：

```python
same = ids[(DATES[ids].dayofweek >= 5) == (date.dayofweek >= 5)]
ids = same if len(same)>=2 else ids
```

`window=7` 时，7 天内恰好只有 **2 个周末日**，因此周末预测退化为"最近 2 个周末的平均值"。两样本估出的负荷曲线尾部毫无覆盖，晚高峰（19–20 时，应急集中时段）实际负荷一旦超预期，只能按 5 倍电价购应急电。

### 1.4 其他结构性问题

- **未使用 6.06M kWh**：其中 3.43M 发生在光伏盈余时段（弃光，代价低），**2.63M 发生在无光伏盈余时段**（日前承诺过量的净浪费，约 2.0M 元）。
- **储能 SOC 触顶 21.3% 的时间**（10,229 / 48,096 时段），触底仅 1.8%。电池长时间充满 → 无法继续吸纳低价电与光伏。
- **应急时段平均 SOC 仅 3,392 kWh**，远低于基准 6,000：晚高峰前电池已被放空。
- **过循环**：日均充电 17,323 kWh、放电 14,032 kWh，容量仅 9,600 kWh，约合 **1.8 次全循环/天**。放电/充电 = 81.0%，恰等于往返效率 0.9²，说明无闲置损耗，但每次循环固定损失 19%，全年损耗约 1.10M kWh。
- **峰谷价差大**：电价 0.3713 ~ 1.3952 元/kWh，**max/min = 3.76 倍**，跨时段套利空间显著。

## 二、优化方案

### 方案① 按精确星期几预测 【✅ 已完成，实测含金量最高】

> **原始诊断被实验推翻。** 初版认为"周末只有 2 个样本 → 估计噪声大"，改法是"拉长回看窗口多取样本"。实测**样本越多周末 MAE 反而越差**（94.66 → 95.09 → 98.73 → 105.92，单调恶化），收益仅 0.23%，机制不成立。

**真实根因**：`predict` 用 `dayofweek >= 5` 把周六周日**混为一类**再取平均，而两者负载模式**相反**：

| 19—20时 | 实际均值 | 混合预测 | 偏差 |
|---|---:|---:|---:|
| 周六 | 526.2 kWh | 660.5 | **高估 134** |
| 周日 | 794.2 kWh | 660.4 | **低估 134** |
| 工作日 | 739.9 | 739.3 | 0.58 |

预测值 660.4 恰为 (526.2+794.2)/2，是一条**两边都不像**的曲线。后果是双向的：周日低估 → 少承诺购电 → 被迫按 5 倍价格买应急电；周六高估 → 多承诺 → 弃电。应急时段负载偏差 +170.81 kWh，非应急时段仅 −5.96，方向完全吻合。

**已实施改法**（`solve_q2.py:51`）：按**精确星期几**匹配，取最近 8 个同一星期几（周一至周日各自独立）的样本均值。`window` 参数语义由"回看天数"改为"回看周数"，并新增模块常量 `LOOKBACK_WEEKS = 8`。

**实测效果**：

| 指标 | 改前 | 改后 | 变化 |
|---|---:|---:|---:|
| 总费用 | 17,260,360.16 | **13,672,895.40** | **−3,587,465（−20.8%）** |
| 应急购电费 | 1,986,478.37 | 445,208.17 | **−77.6%** |
| 未使用电量 | 6,056,901 kWh | 2,670,585 kWh | −55.9% |
| 预测 MAE | 73.28 | 49.46 | −32.5% |

**收益远超预期**：不是初估的 1.0~1.5M，而是 **3.59M**。应急购电费降 77.6%。

**选参机制的处理**：1 月仅 31 天，最多提供 4 个同一星期几样本，**长度上不足以验证回看深度**，原 1 月选参对三个候选给出完全相同得分。故删除该选参，改为一次性全年稳健性检验（`study_lookback.py` → `results/lookback_robustness.json`）：4—24 周范围内节省比例极差仅 **1.06 个百分点**，主结果对该参数不敏感，取 8 周兼顾样本量与季节性漂移。

**风险**：低。预测器改动，不触碰优化模型结构；因果约束（只用昨天及以前数据）保持成立，`verify_outputs.py` 的 `history_latest_date < date` 断言继续通过。

---

### 方案② 场景集扩容与分位数校准

**问题**：场景集由 `residuals[-count:]` 构成（`solve_q2.py:60-63`），即**最近 7 天的残差路径**。样本仅 7 条且时间窗偏窄，尾部覆盖不足。日前 LP 的 `q` 变量按 5 倍价格做 newsvendor 权衡，场景分布不准 → 承诺购电量 `grid` 偏离最优分位点 → 同时产生"未使用"和"应急"两头浪费。

**改法**：
- 按残差分位数构造场景（如 5% / 25% / 50% / 75% / 95% 五条代表性路径）；或
- 扩大历史池（如全部历史残差）后再做场景缩减（scenario reduction）。

**预期收益**：压降未使用中的非光伏部分（2.63M kWh ≈ 2.0M 元），**节省约 0.8 ~ 1.2M 元**。

**风险**：低-中。需重新标定场景数以平衡 LP 规模与代表性。

**实现位置**：`solve_q2.py:60` `scenarios()`。

---

### 方案③ 终端价值函数 `kappa` 改为动态

**问题**：`kappa = p[0]/eta` 是**全年常数** 0.472 元/kWh（`solve_q2.py:174`），且

```python
value[-1] = kappa * np.maximum(EREF - states, 0)      # solve_q2.py:123
```

**高于 6,000 kWh 的部分价值为零**。日内 DP 因此认为"把电留到明天"一文不值，3.76 倍的峰谷价差完全未被跨日利用。

**改法**：终端价值改为依赖次日预测的边际价值（例如 `max_t(p_next)/eta`），或实现跨日的滚动价值迭代。

**预期收益**：**节省约 0.3 ~ 0.8M 元**。

**风险**：中等。必须确保只用次日及更早的预测信息，不得引入未来实际值。

**实现位置**：`solve_q2.py:123` `value_table()` 终端条件 + `solve_q2.py:174` `kappa` 定义。

---

### 方案④ 价值函数：从"边际场景"升级为场景树

**问题**：`value_table` 在每个时段对场景**独立取均值**（`solve_q2.py:127`），丢失路径相关性。函数 docstring 自述"不冒充保留全部时序相关性的精确多阶段DP"。

**改法**：改用场景树 DP，或对尾部场景施加 CVaR 权重。

**预期收益**：**节省约 0.2 ~ 0.5M 元**。

**风险**：高。计算量显著上升，实现复杂度最高，建议最后处理。

**实现位置**：`solve_q2.py:113` `value_table()`。

---

### ~~方案⑤ 抑制过循环~~ 【已否决】

**原假设**：日均 1.8 次全循环、每次损失 19%，疑似过度套利。

**⚠️ 下界结果推翻了该假设**：完美预知下充电量 6.63M kWh、放电量 5.37M kWh，**均高于当前策略**（5.79M / 4.69M）。也就是说，从理论最优看，电池**用得还不够多**，而非过度使用。

**结论**：**不应对充放电加惩罚项**，那只会让结果更差。真正的问题是电池的**充放时机**不对（晚高峰前放空、导致 5 倍应急购电），而非充放总量过大。

**改为**：诊断"为何电池未在高价时段保持足够库存"——这本质上是方案③（终端价值）与方案④（路径相关性）要解决的问题。

## 四、约束与红线

所有优化必须维持以下既有性质，否则结果不可信：

1. **因果性**：每日 0 时不得读取当天未来实际值。`history_latest_date < date` 必须继续成立（`verify_outputs.py:15` 断言）。
2. **物理可行性**：物料平衡、储能动态、SOC ∈ [1200, 10800]、功率 ≤ 5000 kW、禁止同时充放电——由 `verify_outputs.py:18-23` 独立复核。
3. **只读原附件**：不得修改 `附件1.xlsx` / `附件2.xlsx` / `附件5/result2.xlsx`。
4. **可复现**：保持确定性，不得引入随机源。
